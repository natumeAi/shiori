### 1. Preserve source identity independently of layout

**Recommended model:** retain EPUB bytes/content revision, OPF tree, manifest, spine order including `linear="no"`, resource paths/media types, original namespace-aware document tree, element IDs, node kinds and decoded text. Give source nodes immutable identities. A separate render tree records styles, blocks, inline runs and images; every rendered UTF-16 interval maps back to source node/offset intervals. Whitespace collapse, synthetic line breaks, list markers and placeholders require explicit mapping entries, not edits to source text. Canonical statistics coordinates are a third view derived from compatible body text, not from rendered strings.

Important reference behavior:

- Foliate builds each section's CFI base from actual OPF itemrefs (`epub.js:677`) and resolves through OPF paths/`idref` (`:688`). `view.js:431` joins that base to a document CFI with `!`. Do not assume every OPF has `/6` as its spine or derive `sectionIndex` from one numeric step alone. Keep the original zero-based spine index for activity, even when navigation skips non-linear sections.
- Parsing uses the manifest media type. Invalid/non-namespaced XHTML can fall back to HTML parsing (`epub.js:813`). HTML repair, namespaces, entity decoding, CR/LF normalization, inserted body nodes, comments and CDATA are therefore compatibility cases. A generic XML parser or an HTML-to-plain-text package is insufficient evidence of equivalence.
- The reference serializes/reparses content and then applies security transforms (`epub.js:862`; `foliateEngine.ts:470`). Active elements become inert same-position slots, retaining IDs; forms retain children; SVG replacements stay in the SVG namespace (`contentSecurity.ts:13`). Preserve the original tree plus an explicit compatible projection. Deleting whole elements changes later CFI steps; retaining stripped iframe/object descendants in the canonical index can change statistics. Never execute EPUB scripts or fetch arbitrary remote resources to emulate this projection.
- Canonical indexing uses `SHOW_TEXT` (`canonicalText.ts:180`); CFI indexing includes both Text and CDATA (`epubcfi.js:188`). Preserve node kind and test the final parsed/protected DOM equivalent. Treating all XML character data alike is not automatically compatible.

**Fixture gate before renderer selection:** produce synthetic, non-book-prose fixtures with source bytes/media type, browser-equivalent node projection, canonical string/length/hash, representative CFIs and expected resolved source coordinates. Include adjacent text separated by comments/CDATA, escaped IDs, entities/NBSP, malformed XHTML fallback, SVG namespaces, inert scripts/objects, empty nodes, non-linear spine entries and OPF variation. The reference repository stays read-only; fixture/extraction tooling and outputs belong in shiori during implementation. Real-browser results on the target Safari version remain necessary for parsing edge cases; jsdom alone is insufficient.

### 2. Exact CFI bridge and acceptance

Port the pinned Foliate semantics into a pure Dart parser/resolver/serializer with golden compatibility fixtures, independently of whichever EPUB parsing utility is selected. This is a compatibility boundary, not a claim of complete CFI standard support.

| Aspect | Required behavior |
| --- | --- |
| Paths and escaping | Parse `/` steps, `!` indirection and `^` escapes inside assertions; retain IDs and parameters. Never split raw strings on commas/`!` without grammar awareness. See `epubcfi.js:18`, `:107`, `:115`. |
| Children | Even steps address elements; odd slots address text chunks between elements. Ignore comments/PIs; merge adjacent Text/CDATA chunks for offsets, retaining underlying node mapping and virtual edge slots. See `:191`, `:208`, `:234`, `:260`. |
| Text offsets | Offsets count UTF-16 code units, including whitespace. Do not replace them with Unicode scalar, grapheme, canonical-statistics or rendered-text indices. Imported offsets stay exact, even if they fall inside a surrogate pair/cluster; visibility can use the owning complete glyph. |
| Ranges | Support parent/start/end paths, both endpoint mappings and collapse-to-start for restoration. Require full range round-trip equivalence; the saved **start** must be visible, not merely some overlapping text. See `:134`, `:139`, `:288`, `:296`; `foliateEngine.ts:296`. |
| Assertions/comparison | Structural comparison ignores assertion spelling; ID resolution and offset checking must be tested against the pin. Foliate parses text/side/temporal/spatial data but does not implement full assertion correction or temporal/spatial comparison (`:163`). Do not advertise general CFI conformance or silently discard unsupported suffixes. |
| Image/element anchors | Preserve element paths for `img`, outer `svg`, nested `image` and ordinary headings. Resolve the first relevant rendered box; an arbitrary later slice of a long element is not proof. SVG indentation whitespace must not replace the graphic box (`foliateEngine.ts:278`). |

The [EPUB CFI 1.1 specification](https://idpf.org/epub/linking/cfi/) defines UTF-16 character positions and source-tree paths. The reference's exact behavior is additionally constrained by its stricter restore check and pinned implementation; standard support in another package does not establish drop-in compatibility.

**Native page proof:** represent a stable position as source CFI + section identity + immutable layout identity + local page identity/range. Resolve an imported CFI to the same source node/offset, map it into the current layout, round-trip it, and verify its glyph/caret/first-element geometry lies on the foreground page before acceptance. Layout may move that anchor to another page number. During a prepared turn require matching origin, book revision, layout generation, section, target page identity and visible target anchor; matching percentages or CFI strings alone is insufficient (`types.ts:7`; `foliateEngine.ts:388`).

The reference saves a non-whitespace point near the visible text midpoint, falling back to a verified image element on image-only pages (`visiblePageAnchor.ts:2`; `foliateEngine.ts:350`). Native export can use the same policy with its own visible text spans, retaining UTF-16 coordinates. A successful restore must preserve the imported accepted location until verification; no page-1, closest-paragraph or percentage fallback may overwrite it. Failed restoration exposes retry/explicit navigation. Test browser → native → browser, both range endpoints, whitespace/wrap anchors, supplementary characters, image-only pages, TOC jumps and settings reflow.

### 3. Canonical statistics are content coordinates, not page metrics

**Normalization v1 exact algorithm** (`canonicalText.ts:24`, `:174`): walk eligible body Text nodes in document order (document element only when body absent); exclude descendants of `script`, `style`, `noscript`, `template`, SVG and MathML. Count every remaining Unicode code point except Unicode `White_Space`, general categories `Cc`, `Cf`, and unpaired-surrogate `Cs`. Punctuation and combining marks count. No NFC/NFKC, trimming/concatenation separators, grapheme counting or word counting. CSS-hidden prose retains its coordinates and signature, but is not observed. Image alt text and generated layout markers are not body Text nodes. An image-only section can have length zero.

Hash only this canonical stream's UTF-8 bytes with FNV-1a64, offset basis `cbf29ce484222325`, prime `100000001b3`, modulo 2^64; encode lowercase 16-digit hex with `fnv1a64:` prefix (`:63`). Use explicit 64-bit-safe arithmetic, BigInt, or the same 16-bit-limb algorithm. Do not rely on signed overflow or on an unverified Dart regexp's Unicode-property behavior/version. Pin/test the property tables or runtime implementation against the reference fixtures. Maintain canonical-to-source UTF-16 start/end offsets per node; e.g. `a 😀b` maps starts `[0,2,4]`, with the emoji ending at 4 (`readingActivityText.test.ts:36`). Existing hash vectors include empty → `cbf29ce484222325`, `a` → `af63dc4c8601ec8c`, `foobar` → `85944171f73967e8` (`:17`).

**Visibility:** after an accepted stable page has been idle for 300 ms, sample only its actual foreground fragments. Require positive, finite geometry fully inside the intersected viewport/content clip (reference tolerance 1 logical CSS pixel); clipped single characters, hidden/zero-opacity content and missing geometry add nothing. Keep disjoint half-open intervals `[start,end)`, merge overlaps/adjacency, never fill holes or credit entire nodes/sections. Reference uses recursive subdivision with an overall 20,000-measurement limit and yields in 8 ms slices (`visibleText.ts:55`, `:132`, `:153`). Native should preserve conservative outcomes but use cached page/glyph geometry and smaller measured work slices; the browser's 8 ms slice is not a safe 120 Hz native scheduling budget.

Flutter selection boxes omit partially selected multi-code-unit glyphs. Obtain complete cluster bounds/ranges, map those to source code points, and credit eligible code points only when the complete cluster is visibly inside the page. Test combining marks, emoji/ZWJ and ligatures so a glyph-selection shortcut does not silently undercount ordinary text. [TextPainter selection boxes](https://api.flutter.dev/flutter/painting/TextPainter/getBoxesForSelection.html), [Paragraph glyph lookup](https://api.flutter.dev/flutter/dart-ui/Paragraph/getGlyphInfoAt.html), [GlyphInfo](https://api.flutter.dev/flutter/dart-ui/GlyphInfo-class.html). Retain code-point counts even when several code points share one visible cluster.

**Lifecycle and delivery:**

- Observe only `opened`, `navigation`, `layout-restored`; forced `snapshot` does not create activity. Recheck generation, engine/session, accepted CFI/layout and idle readiness after every yield (`activityTracker.ts:177`, `:264`). No preview/prewarm/page-count task contributes text.
- Foreground time runs through ordinary tracking/dragging/preparing/settling/committing, stops for background, blocking settings/TOC, suspension, recovery/error, detach/close. Image viewer keeps time but prevents text sampling (`:75`, `:210`). Map this conservatively to Flutter lifecycle/route visibility; resume starts a fresh clock baseline, never credits the suspended gap.
- Checkpoint every 15 seconds and at lifecycle boundaries; stop/checkpoint closes each span exactly once. Reject non-positive elapsed time, >120-second spans, or >10-second monotonic/wall drift. Split valid duration at local hours/midnight, cumulatively round, preserve observed local date/hour, including DST behavior (`readingActivity.ts:32`, `:100`, `:159`).
- Completion occurs once per reader session: accepted navigation from verified non-final to final (including TOC/slider), or first healthy open of a never-saved one-page book. Reopen at end, recovery, reflow and snapshot do not complete (`:376`). Emit a separate zero-duration completion record with its original date/instant.
- Keep immutable event IDs/payloads in durable, server-scoped storage before sending. Preserve exact serialized event bytes on retry. Single-flight delivery removes only acknowledged IDs; permanent errors remain surfaced, partial/unanswered events retry. Signature mismatch suspends that section/signature's future coverage while time continues (`activityDelivery.ts:7`, `:154`). Do not hash native rendered text into a different signature and keep retrying it.
- Wire bounds: normalization=1; <=50 events/batch, <=32 distinct sections/event, <=256 intervals/section, section index <=100,000, length <=10,000,000; interval end cannot exceed section length. Reference batch body bound 900,000 bytes; ordinary retry grows 5 seconds to 5 minutes (`readingStats.ts:31`; `activityDelivery.ts:85`, `:120`). Server-side union/idempotency remains authoritative.

### 4. Gesture, motion and acceptance contract

Use CSS-pixel-equivalent Flutter logical units; freeze viewport/direction at pointer admission. iOS system edge gestures must remain available. Reference ignores non-primary pointers and non-mouse starts within 20 px of either screen edge (`usePageTurnController.ts:55`). A second finger's cancellation must not undo the tracked gesture. An image tap has priority over page tap zones (`readerController.ts:900`).

| Behavior | Exact reference rule |
| --- | --- |
| Axis lock | Below 10 px on both axes: pending. Horizontal iff `abs(dx) >= 1.2*abs(dy)`, otherwise cancel. Visible displacement begins after the signed 10 px lock offset. |
| Commit | Distance threshold `round(clamp(width*0.28,72,160))`; otherwise velocity threshold 0.45 px/ms over latest 100 ms. Distance wins when both qualify. |
| Boundary | No destination; rubber band `sign(d)*(1-1/(abs(d)*0.35/60+1))*60`. Ordinary drag clamped to one page width. |
| Tap | No horizontal lock and elapsed <=300 ms. Longer hold ignored. Left/right thirds previous/next; exact third boundaries belong to center. Center toggles chrome. |
| Tap/keyboard animation | 420 ms, Hermite start slope 1.3 and end slope 0. This is different from the 300 ms tap-recognition limit. |
| Release settlement | Base `round(260+160*clamp(abs(remaining)/width,0,1))` ms. Launch `max(1.3, projectedSpeed*duration/abs(remaining))`, capped at 3; excessive speed shortens duration, floor 120 ms. Compute from actually rendered displacement, especially reversals. |
| Late neighbor | 80 ms ease-out-cubic catch-up following latest sample, including a held finger. Never jump to a stale sampled displacement. |
| Curve | `v*(p^3-2*p^2+p)+3*p^2-2*p^3`, `p` in [0,1], launch `v` in [0,3]. Use elapsed-time animation, not fixed pixels per frame. |

Sources: `pageTurnGesture.ts:1`, `:31`, `:95`, `:110`, `:121`; `pageTurnEngine.ts:59`, `:87`; `readerController.ts:288`, `:657`.

Keep one current intention plus at most eight FIFO waiting intentions; report overflow explicitly. Rebase a promoted gesture onto the latest accepted origin; cancellation/settings/layout/background/close terminate queued promises and reject stale callbacks. Accepted turns remain accepted if a later callback fails (`readerController.ts:19`, `:525`, `:567`, `:813`).

Prepare outgoing/incoming pages before motion. Animate their offsets together; next sits one viewport to the right, previous one to the left. The dominant preview may update the page label after half-width, but it has no persistence/coverage authority. Hold the incoming surface during verified handoff; only then publish one accepted destination and release old resources. Proof conflict restores the accepted origin without a second speculative turn (`readerController.ts:610`; `pageRenderer.ts:109`). Reduced motion skips animation but still verifies/accepts navigation. Preparation failure may use a verified static turn, as the reference does, and must be counted separately in performance evidence.

Port behavioral cases from `readerTurnProof.test.ts:111`, `readerInputQueue.test.ts:65`, `readerMotionIsolation.test.ts:72`, `readerBidirectionalSlide.test.ts`, and `pageTurnEasing.test.ts`. They are state-machine evidence, not on-device smoothness evidence.

### 5. Text layout, illustrations and bounded preparation

**Recommended technical choice:** pure Dart EPUB/source/CSS processing feeding a dedicated native block/inline compositor using `ui.Paragraph` or `TextPainter`, with immutable prepared page plans. Parsing packages can help, but neither their CFI API nor a scrollable HTML widget proves this pagination contract.

An initial explicit style matrix should cover headings/paragraphs/divisions, spans, bold/italic/emphasis, links, line breaks, ordinary lists/blockquote, alignment/justification, indentation, paragraph margin/padding, text size/weight/family fallback, line height, letter spacing, foreground/background colors and raster/SVG illustrations. Implement cascade/inheritance and a bounded selector/unit subset needed by the samples, including class/type/descendant selectors, source order/specificity and `!important`; the illustrated sample also has `.illust:not(:last-child)`. This is a design matrix to validate, not a promise of full HTML/CSS. Known unsupported content/layout must be detected and explained without losing saved progress; it must never disappear silently. Ruby and complex tables were not found in the four samples and have not been explicitly excluded by the user—do not infer an exclusion from that absence.

Honor actual reader overrides: body font/size; line height and letter spacing on common blocks; wrapping; theme colors on specified elements; images contained without crop/rounded corners (`useReaderSettings.ts:249`). Preserve six font option IDs and tested iPhone fallbacks, rather than claiming Microsoft fonts are installed. Font-size 14–40 step 2, default18; line-height 1.3–2 step0.1, default1.6; letter-spacing 0–0.12em step0.02; margin additions 0–48 step6 (`:22`). Convert `em` letter-spacing using effective font size. Flutter line metrics and actual fallback fonts require visual comparison; matching a slider value alone is not parity.

**Layout mechanics:**

1. Worker isolate: ZIP/resource parsing, source/CSS tree processing, canonical indexing/hash and serializable layout inputs. Load required root-isolate assets before transfer. Keep transfer/copy costs and archive expansion/resource limits bounded.
2. Main isolate: resolve/load fonts, shape and lay out paragraphs, obtain line/cluster geometry and decode/prepare painting resources through supported Flutter APIs. Flutter explicitly says spawned isolates cannot perform `dart:ui`/widget work; do not promise `TextPainter.layout` or `Paragraph.layout` in a worker. [Flutter isolate limitations](https://docs.flutter.dev/perf/isolates).
3. Lay out at final finite content width, obtain line metrics and line-to-source ranges, then pack complete lines/blocks/images into pages. Retain clipped/transformed paragraph slices for paint; do not reshape each page with different line breaks. A first-line indentation placeholder is a candidate requiring tests (including justification): placeholders add U+FFFC to the paragraph buffer, so mark it synthetic and give it no CFI/canonical slot. Preserve explicit whitespace and image mappings. [TextPainter layout](https://api.flutter.dev/flutter/painting/TextPainter/layout.html), [line metrics](https://api.flutter.dev/flutter/painting/TextPainter/computeLineMetrics.html), [Paragraph line boundaries](https://api.flutter.dev/flutter/dart-ui/Paragraph/getLineBoundary.html), [inline placeholders](https://api.flutter.dev/flutter/dart-ui/ParagraphBuilder/addPlaceholder.html).
4. A paragraph layout call is synchronous/non-preemptible. Yielding between paragraphs does not bound one enormous paragraph. Include long unspaced and very large single-paragraph fixtures early; if necessary, prototype context-preserving segmentation at verified line/grapheme boundaries and prove no lost/duplicated/reshaped content. Do not claim arbitrary chunking or a timer makes the cost safe. First-layout waits are explicit preparation states, outside moving-frame windows.
5. Cache line/page maps and source spans; lazily prepare current/previous/next pages and boundary sections. Current-section count precedes speculative neighbors after input needs; whole-book counts may stay unknown. Build/page-number estimates must not supply progress restoration or coverage. Cancel optional work immediately on input, but wait for actual outstanding work to drain before treating the renderer as quiet.
6. Motion path updates only numeric offsets on already prepared surfaces. Use locally owned animation/listenable state and retained/repaint-isolated children, not a Riverpod screen rebuild per tick. No parsing, paragraph layout, image decode initiation, font loading, pagination, storage writes, canonical traversal or expensive telemetry serialization inside pointer/animation callbacks. Flutter still needs UI-frame work for animations; retained layers do not promise compositor-only execution or automatic raster caching.

**Illustrations:** read-only archive inspection confirmed all 14 SVGs in `docs/综上所述，我们证明了初恋 - 02.epub` have a `viewBox`, `width/height="100%"`, and one full-size nested `<image xlink:href="../Images/...jpg">`. Entries include `OEBPS/Text/Cover.xhtml`, `chapter0.xhtml`, `chapter2.xhtml` and subsequent illustration chapters. Shapes include 1443×2048, 2048×1090, 2048×1453. This supports a specific native fast path: resolve the package-relative raster, retain outer SVG identity/box, use contain aspect fitting, and open the original image in the viewer. The reference guards this optimization against transforms/crops/masks/filters/multiple graphics (`contentImage.ts:403`). Do not apply it to arbitrary SVG. General SVG illustration support needs a tested Flutter-compatible renderer/resource resolver; unsupported SVG must be surfaced, never stripped. SVG prose remains excluded from canonical stats even when visually painted. All three other samples' `<img>` resources and image-only covers remain fixtures.

**Cache identity/lifetime:** include server identity + book/content revision, spine resource, parser/normalizer/style-engine version, viewport/content insets, typography/actual font readiness, scale/direction and layout generation. Appearance generation covers theme/image rendition changes. Accepted-position revision scopes neighbor proofs separately from reusable source/paragraph data (`bufferTypes.ts:4`; `pageBuffer.ts:9`). A changed font/image intrinsic size, setting, viewport or source revision invalidates affected geometry and restores from the last verified CFI. Never reuse a page map merely because book ID is unchanged. Bound source/paragraph/image/page caches by bytes plus ownership counts, count loading/leased/retiring objects against budgets, and dispose native paragraph/picture/image resources after leases end. The reference limits additional surface owners to two (`pageBuffer.ts:89`); native cache byte ceilings require device evidence rather than copying DOM-owner counts as a memory guarantee.

### 6. Defensible Windows/iPhone performance protocol

This is a **proposed reviewable engineering gate**, not measured results or an already-agreed numerical SLA. It fits the chosen release/AOT sideload route; see `ios-device-workflow.md` for build/install/renewal constraints.

1. First milestone proves a hosted macOS release-device build can be signed/installed from Windows, launches independently, exports diagnostics through Files/share workflow and updates without deleting state. Then prove the measurement fields actually arrive on this device before relying on them. No Mac-connected Instruments session or paid hardware/service is an assumed dependency.
2. Export build/toolchain/engine IDs, device/iOS, viewport/DPR, font/settings, book digest, scenario/run IDs, power/thermal conditions where observable, and requested/reported display refresh information. Separate reduced-motion, low-power/thermal/system-restricted cadence from nominal high-refresh runs; keep those runs as correctness evidence.
3. Record a bounded in-memory event ring: input receipt and admitted/queued/rejected result, preparation start/end/cache state, first motion submission, motion end, verification/acceptance, generation, page proof and cold/warm status. Append all `FrameTiming` build/raster durations, vsync overhead, totalSpan, phase timestamps/frame numbers, and scheduled-frame timestamps during active motion. Export/serialize after scenarios, not each frame. Correlate using validated monotonic epochs/IDs—`FrameTiming` timestamps need not share `DateTime`'s epoch. Release timing reports are batched, roughly once per second; callback arrival is not frame presentation time. [Release timings](https://api.flutter.dev/flutter/scheduler/SchedulerBinding/addTimingsCallback.html), [FrameTiming](https://api.flutter.dev/flutter/dart-ui/FrameTiming-class.html).
4. For a nominal 120 Hz window, use 8.333 ms as budget. Report UI and raster P50/P95/P99/max and over-budget counts **separately**; report totalSpan as latency, not reciprocal FPS. Count scheduled-vsync gaps only while motion is active; resting pages do not need 120 newly rendered frames. A reasonable initial target for plan review is >=99% of motion frames within each UI/raster budget, no unexplained >=50 ms stall, and P95 input-receipt-to-first-motion-submission <=2 nominal intervals for warm admitted input. Queue wait, cold preparation and handoff need separate distributions; the 420 ms intended animation is not input latency. These thresholds must be validated/adopted in the parent plan, not represented as existing user approval.
5. Run at least three repeats of continuous drag/settle, taps, reverse-before-release, rapid FIFO turns, first/last-page rebound, illustrated pages, cross-chapter turns, large chapter/single paragraph, font/size changes, background/resume, and network outage. Include a >=100-turn alternating sequence and a longer repeated navigation run to reveal resource growth. Retain cold runs separately from warmed runs; report static fallback rate and correctness failures, never hide them behind good average FPS. Inspect no content jumps/blanks/crops and exactly one accepted destination per committed input.
6. Report **engine timing**, **scheduled/display-link cadence**, and **actual presentation/input-to-photon** as distinct evidence levels. `Display.refreshRate` is display metadata, not proof of presented reader frames. A CADisplayLink diagnostic bridge, if chosen later, can report cadence but does not identify whether the particular Flutter content frame was displayed. Apple exposes actual drawable presentation through `MTLDrawable.presentedTime`/presented handlers; stock Dart app-level timing APIs do not expose that Flutter drawable. Do not assume a small plugin can attach it or that an engine modification is in scope. [Flutter Display](https://api.flutter.dev/flutter/dart-ui/Display-class.html), [Apple display-link guidance](https://developer-mdn.apple.com/videos/play/wwdc2021/10147/), [Metal presentation time](https://developer.apple.com/documentation/metal/mtldrawable/presentedtime).
7. Make presentation-evidence feasibility a bounded early spike, not a promise of a Windows-only system trace. If no supported export is demonstrated, record that limitation immediately. Independent high-speed video is a conditional alternative, not equipment the user owns. Ordinary screen recording or an on-screen FPS counter is insufficient to prove 120 distinct visible frames. Without such evidence, the honest result is “release-device engine/cadence gate passed; physical presentation unverified.” Do not close AC4 as full physical proof. If obtainable evidence cannot meet the final acceptance wording, the evidence standard is a residual user-owned review decision, not permission to fabricate a pass or to re-ask already resolved device/budget questions.

## Caveats / Not Found

- No candidate native layout engine has yet passed interoperability, memory, fidelity or physical-iPhone performance gates. No test suite or benchmark was run in this research.
- No backend change is demonstrated as necessary for canonical activity/CFI compatibility; implement the existing contract first. A server content-revision/cache-invalidation mechanism is a separate API research dependency.
- The four local novel samples are a seed corpus, not proof of arbitrary novel EPUB support. Parser repair, embedded fonts, ruby, complex SVG and large single paragraphs need explicit fixtures/behavior before coverage claims. A general “supports EPUB/CSS” promise is indefensible.
- Package/Flutter API documentation was checked on 2026-10-22. Pin the eventual cloud Flutter/engine version compatible with shiori's Dart constraint and verify every selected API there; no SDK upgrade or dependency selection was performed.
- The exact protected/browser DOM, not raw XML text flattening, is the interoperability oracle. XML CDATA and sanitizer-generated structure are easy-to-miss cases.
- Physical 120 Hz presentation and touch-to-photon proof remain unestablished with the currently documented tools. Instrumented release timing is valuable evidence with an explicit limit, not a substitute claim.
